# «Грибница» — ТЗ для фронтенда

> Самодостаточный документ: всё, что нужно фронту, здесь. Бэкенд обязан отдавать данные **ровно** в форме
> из `docs/mock/*.json`. Если чего-то не хватает — сразу пиши Даниилу, не обходи на фронте.

## 0. Коротко

**Продукт.** Инструмент AML-аналитика банка. На вход — переводы от 81 известного курьера (наркотрафик),
2 248 клиентов, 3 119 связей. На выход — роль каждого клиента, группы, кого проверять первым и почему.

**Метафора для питча.** Банк срывает грибы (курьеров), а они вырастают снова. Мы показываем грибницу.

**Пользователь.** AML-аналитик банка, не программист. Интерфейс на русском, понятный без ML-образования.

**Как жюри проверяет экран (обязательный пункт кейса):** называет любой gid → мы находим его на схеме →
показываем его связи, направление денег и роль → объясняем роль за минуту.

**Дедлайн.** 18:00 фиксируется репозиторий. Финальная сборка фронта — в репозитории к **17:00**.

## 1. Жёсткие правила

1. **gid — всегда строка.** Это 18-значные числа; JS портит числа длиннее 16 знаков. Никогда
   `Number(id)`, `parseInt(id)`, `JSON` с числовыми gid. Во всех ответах API поле называется `id`.
2. **Готовая сборка коммитится в `web/dist/`.** Бэкенд раздаёт её по адресу `/`. Эксперты запускают только
   Python — Node у них может не быть. Всё (библиотеки, шрифты) должно быть **внутри сборки**, без CDN.
3. **Адреса API относительные** (`/api/...`). Для разработки — переменная базового адреса (например,
   `VITE_API_BASE=http://localhost:8000`); CORS на бэкенде открыт.
4. **Тексты выводов берём из API как есть.** Никаких своих формулировок про виновность. Разрешено:
   «признаки…», «гипотеза», «рекомендуем проверить». Запрещено: «преступник», «виновен», «украл»,
   «организатор» как утверждение.
5. **Цвета и названия ролей — из `/api/meta`**, не хардкодить.
6. **Не хардкодить gid** нигде, в том числе в демо-кнопках.
7. Твоя зона — только папка `web/`. В остальные файлы репозитория не коммить.
8. Коммит минимум раз в час (правило хакатона — иначе дисквалификация всей команды).

## 2. Что строим — по приоритету

### MUST — к 15:30 (без этого кейс не засчитан)
1. **Схема сети.** Узлы по координатам `x, y` из API (раскладку не считать — она готова). Стрелки
   направления денег. Цвет = роль (переключатель: роль / кластер). Размер = `priority`. Курьеры
   (`is_seed`) — другой формой (ромб). `truncated` — пунктирная обводка.
   **По умолчанию показывать топ-30 и их соседей**, кнопка «Весь граф» (2 248 узлов — «клубок», подписи
   только при зуме).
2. **Поиск по gid** (полный или часть): зум на узел, подсветка его связей (`/api/node/{id}/ego`) и курьеров,
   чьи деньги до него доходят (`upstream_seeds` из карточки).
3. **Карточка узла** (клик по узлу или строке списка): роль, устойчивость («роль устойчива в 49 из 50
   вариантов порогов»), метрики, `evidence`, блок **«Почему эта роль»** из `rule_trace` (✓/✗, значение,
   порог), топ плательщиков и получателей (кликабельны).
4. **Список «Кого проверять»** (`/api/top?kind=check`): ранг, gid, роль, приоритет, почему. Клик → узел.

### SHOULD — 15:30–17:00 (это выделяет нас на Demo Day)
5. **Вкладка «Лестница денег».** Санкей из `/api/sankey`: колонки = колена 0–4, толщина = ₸. Сноска из
   `skipped_kzt`: «23 % денег ходит по кругу или вбок — см. ядро».
6. **Вкладка «Блокировка».** Клик по узлу на схеме гасит его → `POST /api/block` → счётчики
   «поток денег курьеров −X %», «до верхних уровней −Y %», «фрагментов сети: N». Кнопки-пресеты из
   `/api/resilience`: «План блокировки», «Топ проверки», «Топ по обороту», «10 случайных» — сравнение
   столбиками. Подпись: **«Проверять и блокировать — разные задачи»**. Кнопка «Сбросить».
7. **Вкладка «ИИ-аналитик».** Справка (`/api/brief`, markdown), поле вопроса (`POST /api/ask`). В тексте
   `[gid:123…]` → кликабельная ссылка на узел. Значок «✓ сверено с графом» или «⚠ не сверено: …» из
   `issues`. Раскрывающийся список `tool_calls` («какие запросы к графу сделал ИИ»). Если
   `ai_enabled=false` в `/api/health` — показывать только справку с пометкой «сохранённая версия».
8. **Переключатель «Показать ядро»** — подсветить узлы с `in_core=true` (кольцо из 85 узлов, где деньги
   ходят по кругу; там большинство координаторов).
9. **Список «План блокировки»** (`/api/top?kind=block`) рядом со списком проверки.

### COULD — если остаётся время
10. Вкладка «Следующий запрос» (`/api/next-requests`) — таблица.
11. Вкладка «Кластеры» (`/api/clusters`) — клик подсвечивает кластер на схеме.
12. Ползунок по дням июля (эндпоинт `/api/timeline` появится, только если договоримся).

### Предлагаемая раскладка
```
┌──────────────────────────────────────────────────────────────────────┐
│ Грибница   [Сеть] [Лестница денег] [Блокировка] [ИИ-аналитик]  поиск │
├───────────────┬────────────────────────────────────┬─────────────────┤
│ Кого проверять│                                    │ Карточка узла   │
│ План блокир.  │           схема / вкладка          │ Почему эта роль │
│ (списки)      │                                    │ связи           │
└───────────────┴────────────────────────────────────┴─────────────────┘
```
Сверху — полоса со сводкой из `/api/meta.network`: узлов, связей, курьеров, оборот.

## 3. Цвета и форматирование

Роли (итоговые цвета придут из `/api/meta`, это стартовые):

| id | Название | Цвет |
|---|---|---|
| coordinator | Координатор | `#D1495B` |
| consolidator | Точка сбора | `#EDAE49` |
| distributor | Распределитель | `#8E6BBF` |
| transit | Транзит | `#3E8ED0` |
| terminal | Конечный получатель | `#4F9D69` |
| peripheral | Периферия | `#A0A4AB` |

Суммы: `< 1 млн` → «850 тыс. ₸», иначе «3,2 млн ₸». gid на экране показывать целиком (моноширинный
шрифт), в тесных местах — последние 6 цифр с полным gid во всплывающей подсказке.

Библиотеки — на твой выбор. Проверенные варианты под 2 248 узлов: Cytoscape.js (layout `preset`), Sigma.js
+ graphology; Санкей — ECharts.

## 4. API

База: тот же адрес, что и страница (`/api/...`). Все ответы — JSON. Ошибки:
`{"error": "not_found", "message": "..."}` с кодом 404 / 400 / 503.

| Метод и путь | Что отдаёт | Мок |
|---|---|---|
| `GET /api/health` | статус, включён ли ИИ | `health.json` |
| `GET /api/meta` | роли (название, цвет, число), сводка сети, пороги | `meta.json` |
| `GET /api/graph` | все узлы (лёгкие поля + x, y) и все рёбра | `graph.json` (1,1 МБ, реальные данные) |
| `GET /api/node/{id}` | карточка: метрики, evidence, rule_trace, upstream_seeds, плательщики, получатели | `node.json` |
| `GET /api/node/{id}/ego?hops=1` | окрестность узла: `center`, `nodes` (id), `edges` | `ego.json` |
| `GET /api/search?q=…&limit=10` | поиск по части gid | `search.json` |
| `GET /api/top?kind=check&limit=30` | кого проверять: rank, id, role, priority, why | `top_check.json` |
| `GET /api/top?kind=block&limit=20` | план блокировки: step, id, role, cut_kzt_marginal, reach_kzt_after, why | `top_block.json` |
| `GET /api/clusters` | кластеры: размер, курьеры, оборот, top_ids, гипотеза | `clusters.json` |
| `GET /api/sankey` | узлы и связи Санкея + `skipped_kzt` | `sankey.json` |
| `GET /api/resilience` | готовые сравнения стратегий для N = 5/10/20 + baseline | `resilience.json` |
| `POST /api/block` | тело `{"ids": ["…"]}` → baseline, after, drop_reach_pct, drop_deep_pct | `block_response.json` |
| `GET /api/next-requests` | что запросить дальше | `next_requests.json` |
| `GET /api/brief` | справка ИИ: markdown, verified, issues, cached | `brief.json` |
| `POST /api/ask` | тело `{"question": "…"}` → answer, verified, issues, gids, tool_calls; 503, если ИИ выключен | `ask_response.json` |

### Поля узла в `/api/graph`
`id, x, y, role, role_score, cluster, priority, rank (1–30 или null), is_seed, depth (0–4), truncated,
in_core, in_kzt, out_kzt, evidence`. Рёбра: `source, target, sum_kzt, n_tx`.

### Карточка `/api/node/{id}`
```json
{
  "id": "…", "role": "coordinator", "role_label": "Координатор", "role_score": 1.0,
  "stability_text": "роль устойчива в 50 из 50 вариантов порогов",
  "priority": 1.0, "rank": 1, "cluster": 3, "is_seed": false, "depth": 2,
  "truncated": false, "in_core": true,
  "metrics": {"in_deg": 19, "out_deg": 61, "in_kzt": 1817300, "out_kzt": 4986156,
              "pass_through": 2.74, "hold_median_days": 0, "seed_reach": 7,
              "cut_kzt": 8208866, "sync_max_payers": 4},
  "evidence": "Кандидат в координаторы: собирает от 19 плательщиков…",
  "rule_trace": [{"role": "coordinator", "matched": true,
                  "checks": [{"label": "плательщиков ≥ 8", "value": 19, "ok": true}]}],
  "upstream_seeds": ["…"],
  "payers": [{"id": "…", "sum_kzt": 0, "n_tx": 0, "role": "transit"}],
  "recipients": [{"id": "…", "sum_kzt": 0, "n_tx": 0, "role": "terminal"}]
}
```
`metrics.*` могут быть `null` (например, `pass_through` у курьеров) — показывать «—» с подсказкой
«у курьеров входящие занижены выгрузкой».
