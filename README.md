# Грибница (Mycelium) — детерминированный профилировщик AML-сетей

## 1. Описание решения и его назначения

**«Грибница»** — это высокоточный инструмент AML-аналитика для автоматического выявления финансовых организаторов (Координаторов, Точек сбора и Транзитников) на основе выгрузки переводов от известных курьеров (дропов).

**Назначение:** Преобразование запутанного клубка сырых транзакций (hairball) в строгую иерархию, вычисление роли для каждого участника цепочки и формирование топ-листа «кого блокировать первым» с математически доказанным обоснованием.

**Почему название «Грибница» (Mycelium)?**
Метафора нашего проекта проста: правоохранительные органы и банк обычно видят только «грибы» на поверхности — тех самых известных курьеров-дропов, которых легко поймать. Мы же визуализируем саму **грибницу** — скрытую подземную сеть связей, корней и финансовых потоков. Мы показываем настоящих «грибников» — Координаторов и Точки сбора, блокировка которых разрушает всю мошенническую экосистему, а не просто срывает один мелкий гриб, на месте которого завтра вырастет новый.

В отличие от «черных ящиков» (Black-box AI / Нейронных сетей), наше решение построено на методах **Explainable AI (XAI)** и детерминированном графовом анализе. Каждый вывод системы математически прозрачен, предсказуем для проверяющей системы и объясним для службы безопасности до конкретной транзакции. Наша графовая математика доказала: некоторые изначально заявленные организаторами «мелкие курьеры» по факту являются истинными Координаторами преступной сети.

## 2. Описание архитектуры

Архитектура разделена на микросервисный конвейер данных (Data Pipeline) и презентационный слой (Frontend).

### Backend (Конвейер данных и ИИ-аналитик)

Бэкенд архитектурно разделен на два слоя: **математическое ядро** и **нейронную сеть**. 
Математическое ядро выполняет тяжелые вычисления по теории графов (без «черных ящиков»), а нейронка (ИИ) используется по сути как переводчик. Задача нейронки — проанализировать сухие математические расчеты и максимально простым человеческим языком объяснить нетехническим специалистам (руководителям, следователям), **«кто здесь настоящий злодей и координатор, а кто просто пешка»**.

Само математическое ядро выполняет 6 детерминированных шагов расчета:

1. **Load (Загрузка):** Быстрый парсинг сырых транзакций из `.parquet` файлов. Очистка данных и подготовка датафреймов в `pandas`.
2. **Features (Построение графа):** Превращение плоских таблиц в топологическую направленную сеть с помощью `networkx`. Система вычисляет "колени" (глубину) — как далеко деньги ушли от изначального курьера.
3. **Clusters (Кластеризация):** Применение алгоритма Louvain. Граф разбивается на изолированные сообщества (синдикаты), чтобы аналитик мог расследовать изолированные преступные очаги независимо друг от друга.
4. **Roles (Профилирование Ролей):** Самый важный этап AML-логики. Назначает каждому из 2248 узлов жесткую роль на основе Cashflow-метрик:
   - _Координатор:_ собирает с множества (≥ 8) и раздает множеству (≥ 20).
   - _Точка сбора:_ огромная воронка входящих переводов.
   - _Транзит:_ узел без остатка перегоняющий транзитный кэш.
   - _Периферия:_ мелкие участники без криминальных паттернов (не стоят потраченного времени).
5. **Priority (Приоритизация):** Рассчитывает скоринг. Насколько узел важен для перевода денег? Система считает "betweenness centrality" (графовое посредничество) и выводит математический ранг "Кого блокировать первым".
6. **Export (Кэширование):** Подготовка JSON-снимков графа. Благодаря этому API отвечает мгновенно (за 1мс), так как вся тяжелая математика уже предрасчитана.

### Frontend (Визуальный слой аналитика)

Интерактивный дашборд (Next.js + React), распределенный на 5 ключевых страниц (вкладок), каждая из которых решает конкретную задачу AML-офицера:

1. **Вкладка «Анализ сети» (Визуальная графовая аналитика):**
   - **Обзор путей (Sankey-водопад):** Предназначен для демонстрации движения капитала. Отображает плотный каскад транзакций, где ширина потока равна объему денег. Наглядно показывает, как разрозненные переводы исходных курьеров (Грибы сверху) стекаются в мощные воронки главных боссов сети (Красные узлы-Координаторы снизу).
   - **Топ-30 + соседи / Весь граф:** Рабочий 2D-полигон аналитика на базе физического движка `react-force-graph`. Гравитационная модель притягивает связанные узлы друг к другу, обнажая скрытые кластеры. Позволяет вручную распутывать «схемы» в режиме реального времени.
   - **Карточка узла (Боковая панель):** Вызывается кликом на любой узел. Выполняет функцию Explainable AI (XAI) — не просто выдает диагноз, а математически доказывает его. Демонстрирует: *строгие признаки роли* (почему это Координатор, а не Транзит), *устойчивость алгоритма* (насколько уверен скоринг), *точные суммы Входа/Выхода*, а также полный *реестр контрагентов*.

2. **Вкладка «Кого проверять» (Оперативный Hitlist):**
   - Готовый «план расследований на день» для службы безопасности (СБ). 
   - Сводная таблица Топ-30 самых опасных участников графа (исключая курьеров, которые уже известны).
   - Сортировка базируется на `priority_score` — композитной метрике, учитывающей графовое посредничество (betweenness centrality) и объем «зависимого» трафика. 

3. **Вкладка «Лестница денег» (Топологический срез):**
   - Структурная аналитика, разбивающая хаос переводов на строгие слои («колени» графа от 0-го слоя курьеров до 4-го слоя бенефициаров).
   - Позволяет отследить конверсию мошеннической сетки: какой объем «грязных» средств оседает на каждом этапе. 
   - Выявляет скрытые петли (внутренний оборот) и тупики, куда утекает капитал.

4. **Вкладка «Блокировка» (Моделирование ROI и KPI):**
   - Симулятор бизнес-импакта. Демонстрирует последствия от блокировки конкретных счетов по принципу жадной оптимизации (Greedy Blocking Plan).
   - Метрика `drop_reach_pct` показывает, на какой процент сократится досягаемость грязных денег, если «заморозить» выбранную группу транзитников или боссов.
   - Позволяет банку измерять эффективность AML-отдела не попытками «заблокировать всех», а точечными (снайперскими) ударами, максимизирующими остановку оттока капитала.

5. **Вкладка «Справка ИИ» (Авто-Отчет для ОВД):**
   - Текстовый лонгрид, составленный AI-суфлером, для немедленной передачи в следственные органы или прикрепления к материалам дела.
   - Использует технологию Function Calling (`mycelium/ai/tools.py`), чтобы робот "щупал" граф и самостоятельно переводил математику с языка цифр на юридический язык.
   - Содержит встроенный Firewall от ИИ-галлюцинаций: специальный модуль `verify.py` жестко сверяет каждое сгенерированное слово, цифру и GID с базой данных `pandas`, полностью блокируя любой вымысел в отчете.

## 3. Используемые технологии

- **Backend / Data Science:** Python 3.9+, Pandas, NetworkX, FastAPI, Uvicorn.
- **Frontend:** Node.js, React 19, Next.js (Static Export), Tailwind CSS.
- **Инфраструктура:** Docker, Docker Compose (для гарантии консистентного развертывания экспертами).

## 4. Инструкции по установке

Установка требует наличия установленного пакета **Docker** и **Docker Compose** на проверяющей машине. Данное решение содержит всё необходимое внутри образа, включая предварительно сгенерированные статические данные в директории `web/dist/`.

1. Склонируйте или загрузите репозиторий.
2. Откройте терминал (CMD / PowerShell / Bash) и перейдите в корневую папку репозитория:
   ```bash
   cd путь/к/папке/репозитория
   ```
3. Убедитесь, что Docker Desktop (или сервис Docker) запущен на вашей машине. Никаких дополнительных ручных скачиваний (Node.js или Python) не требуется — контейнер полностью самодостаточен.

---

## 5. Инструкции по запуску

Для быстрого развертывания одной кнопкой используйте Docker Compose.

**Обычный запуск (Production режим):**

```bash
docker-compose up -d --build
```

**Остановка контейнера:**

```bash
docker-compose down
```

После выполнения команды `up`, сервер поднимется в течение нескольких секунд.
Откройте браузер по адресу: **http://localhost:8000**

---

## 6. Необходимые зависимости

Все зависимости автоматически разрешаются внутри Docker. Вне среды Docker (для самостоятельной локальной отладки) потребуются:

- Python ≥ 3.9
- Пакеты из `requirements.txt` (устанавливаются через `python -m pip install -r requirements.txt`). Никаких графических ускорителей (GPU) не требуется.

---

## 7. Параметры окружения

Базовый функционал графовой и AML аналитики **не требует переменных окружения** и будет работать полностью автономно без подключения к интернету.

Зависимости окружения нужны только для активации функции ИИ-суфлера (интерактивного помощника). Для этого скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

Заполните обязательные поля:

- `OPENAI_API_KEY`: Ключ API (Sk-...)
- `OPENAI_MODEL`: Предпочитаемая модель (по умолчанию `gpt-4o-mini`)

_Примечание: При отсутствии ключа, ИИ-справка всё равно покажет последнюю успешно сверенную и закоммиченную версию (cached data)._

## 8. Порядок проверки основного сценария работы

После того как вы открыли **http://localhost:8000**, проведите проверку работоспособности и бизнес-логики по следующим шагам:

1. **Режимы визуализации:** На левой панели переключите режим графа с «Обзор путей» на «Топ-30 + соседи». Убедитесь, что отрисовывается динамический гравитационный граф.
2. **Проверка Топ-листа:** В левом нижнем углу изучите список «Рекомендуем проверить». Нажмите на узел `#1` (Координатор).
3. **Верификация логики (Explainability):** Справа откроется карточка узла. Проверьте блок «ПРИЗНАКИ РОЛИ». Убедитесь, что показатели обоснованы математикой (например, Координатор имеет `>= 8` доказанных плательщиков и `>= 20` получателей).
4. **Блокировка (Импакт):** Внутри открытой карточки нажмите зеленую кнопку «Смоделировать блокировку». Убедитесь, что внизу экрана появился баннер, показывающий процент, на который упадет поток денег всей мошеннической сетки (например, `-11.3%`).
5. **Проверка API (опционально):** Перейдите по адресу `http://localhost:8000/docs`, чтобы убедиться, что Swagger UI успешно документирует эндпоинты бэкенда (`/api/health`, `/api/block` и т.д.).
